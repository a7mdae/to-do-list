1. نظرة عامة على المشروع (Project Overview)
--------------------------------------------------------------------------------
يهدف هذا المشروع إلى بناء منصة ويب تفاعلية فائقة الاحترافية مصممة خصيصاً ليقدمها طالب BTEC IT Level 3
أمام لجنة من مهندسي الأمن السيبراني وأساتذة التقييم.

المنصة تستعرض ثلاث دراسات حالة لحوادث أمنية واقعية حقيقية حدثت في كبرى المنصات العالمية:
1) Instagram: ثغرة الاستيلاء على الحساب (Account Takeover) - محور المصادقة (Authentication).
2) Snapchat: ثغرة تزوير الطلب من جهة الخادم (SSRF) - محور أمان الخادم (Server-Side Security).
3) Shopify: ثغرة الوصول غير المصرح به للكائنات (IDOR) - محور التفويض والصلاحيات (Authorization).

جميع التجارب تتم داخل بيئة محاكاة برمجية آمنة 100% داخل المتصفح (Client-Side Sandboxed Simulations)،
دون إجراء أي اتصال حقيقي بالمنصات أو البنية التحتية، مع الالتزام التام بمعايير السلامة الأخلاقية.

--------------------------------------------------------------------------------
2. الفلسفة التعليمية واللغوية (Language & Educational Philosophy)
--------------------------------------------------------------------------------
- اللغة الأساسية: اللغة العربية الواضحة والبسيطة مع دعم كامل للكتابة من اليمين لليسار (RTL).
- المصطلحات الإنجليزية: تظهر جنباً إلى جنب مع المصطلح العربي (مثل: المصادقة - Authentication).
- قاعدة الطبقات الثلاث لشرح أي مفهوم تقني (The 3-Layer Rule):
  1. المصطلح التقني (Technical Term)
  2. الشرح المبسط جداً (Simple Explanation - ماذا يعني؟)
  3. مثال واقعي من الحياة اليومية (Everyday Life Analogy)
- تمييز الفرق الجوهري بين المصادقة والتفويض:
  * المصادقة (Authentication) تسأل: "من أنت؟"
  * التفويض (Authorization) يسأل: "ماذا يُسمح لك أن تفعل؟"
  * أمان الخادم (Server-Side Security) يسأل: "إلى أين يُسمح للخادم أن يتصل؟"

3. المكونات والميزات الرئيسية للموقع (Key Features & Components)
--------------------------------------------------------------------------------

أ. الصفحة الرئيسية (Hero & Landing Dashboard):
- عنوان فخم: "مختبر الثغرات السيبرانية - Cybersecurity Vulnerability Lab".
- شعار فرعي: "ثلاث ثغرات حقيقية — ثلاث منصات مشهورة — ثلاث محاكاة تفاعلية آمنة".
- تنبيه الأمان الدائم: "جميع التجارب الموجودة هنا محاكاة تعليمية معزولة ولا يتم فيها الاتصال أو الهجوم على أي نظام حقيقي".
- بطاقات المنصات الثلاث مع مؤشرات الصعوبة (سهل / متوسط / متقدم) وتحديد مجال الأمان لكل منها.

ب. المساعد التفاعلي للمصطلحات (💡 ما معنى هذا المصطلح؟):
- نافذة منبثقة تفاعلية (Interactive Modal / Drawer) ومؤشرات سريعة (Tooltip Badges).
- عند الضغط على أي مصطلح في أي صفحة يظهر كرت أنيق يشرح المفهوم بطبقاته الثلاث.

ج. صفحات دراسة الحالة (Case Studies Architecture) - لكل حالة 8 أقسام محددة:
1. ماذا حدث؟ (The Real Incident Overview) - حقائق موثقة دون مبالغة.
2. ما هي الثغرة؟ (Vulnerability Definition).
3. كيف تعمل الفكرة؟ (How it Works Diagram).
4. التجربة التفاعلية الآمنة (Live Interactive Sandbox - النسخة المصابة).
5. ما الخطر؟ (Business & Security Impact).
6. كيف نحمي النظام؟ (Mitigation & Best Practices).
7. إعادة التجربة بعد الإصلاح (Secure Mode Sandbox - النسخة المحمية).
8. المصادر الرسمية الموثقة (HackerOne, CVEs, Security Disclosures).

د. المحاكاة التفاعلية لكل حالة (Interactive Safe Sandboxes):
1) إنستغرام (Instagram - Authentication):
   - السيناريو: استعادة الحساب للمستخدم الافتراضي (alex_demo).
   - النسخة المصابة: غياب تحديد معدل الطلبات (Rate Limiting) على رمز التحقق المكون من 6 أرقام، مما يسمح بمحاكاة هجوم التخمين السريع والسيطرة على الحساب.
   - النسخة الآمنة: تفعيل Rate Limiting، قفل المحاولات بعد 3 مرات خاطئة، وطلب تأكيد إضافي (Lockout & CAPTCHA).

2) سناب شات (Snapchat - SSRF):
   - السيناريو: ميزة جلب الصور / الروابط عبر الخادم.
   - النسخة المصابة: الخادم يطلب عناوين مدخلة بشكل أعمى، وعند طلب رابط داخلي وهمي مثل (mock-internal-service أو 169.254.169.254) يعيد الخادم بيانات حساسة افتراضية.
   - النسخة الآمنة: الخادم يطبق قائمة بيضاء (Domain Allowlist) ويفحص عنوان الـ IP ويمنع العناوين الداخلية والخاصة (RFC 1918 & Cloud Metadata) مانعاً التسريب.

3) شوبيفاي (Shopify - IDOR):
   - السيناريو: مستخدم (أحمد - ID 1001) يملك ملف report-A.pdf، ومستخدم (محمد - ID 1002) يملك report-B.pdf.
   - النسخة المصابة: أحمد يغير الرقم المعرف إلى 1002، النظام يتحقق أنه مسجل دخول (Authentication: OK) لكنه لا يتحقق من ملكية الملف (Authorization: Ignored)، فيتم تسريب تقرير محمد!
   - النسخة الآمنة: النظام يفحص شرط الصلاحية: (current_user.id == file.owner_id)، ويرفض الطلب: "403 Access Denied - تم رفض الوصول لعدم امتلاك الصلاحية".

هـ. وضع العرض التقديمي المباشر (🎤 وضع العرض - Presentation Mode):
- زر بارز لتفعيل وضع العرض المكبر المناسب لشاشات أجهزة العرض (Projectors).
- إخفاء العناصر غير الضرورية والتركيز على شرائح العرض مع أزرار (التالي / السابق).
- شريط زمني مقترح للعرض (5 إلى 7 دقائق).
- قسم مدمج قابل للطي في كل شريحة: "🎤 ماذا أقول؟" يحتوي على نص جاهز باللغة العربية الطبيعية، يمكن للطالب قراءته أو الاستعانة به ليشرح الفكرة بثقة كخبير أمني.

و. صفحة المقارنة والخلاصة ("ماذا تعلمنا من الحالات الثلاث؟"):
- جدول ومخطط هيكلي يربط الحالات الثلاث بطبقات الحماية (Defense in Depth):
  * Instagram -> المصادقة (من أنت؟)
  * Snapchat -> أمان الخادم (إلى أين يصل الخادم؟)
  * Shopify -> التفويض والصلاحيات (ماذا يحق لك؟)
- الرسالة الختامية: الأمان لا يعتمد على جدار واحد، بل على تكامل الطبقات معاً.

4. المكدس التقني المختار (Technology Stack)
--------------------------------------------------------------------------------
- البيئة الأساسية: React 18+ مع Vite لبناء تطبيق ويب فائق السرعة وخفيف الوزن.
- التنسيق والتصميم: Tailwind CSS مع نظام ألوان داكن عصري (Dark Cybersecurity Aesthetic):
  * الخلفية: أسود وأزرق كحلي داكن (Dark Obsidian / Slate).
  * التأثيرات: زجاجي ناعم (Glassmorphism & subtle borders).
  * ألوان المؤشرات: Cyan (سيان رقمي)، Emerald (أخضر للأمان)، Rose (أحمر للثغرات)، Amber (برتقالي للتنبيهات).
  * دعم كامل لاتجاه RTL والخطوط العربية الحديثة (Cairo / Tajawal).
- الأيقونات: Lucide Icons لتمثيل دروع الأمان، الخوادم، المفاتيح، والأسهم.
- التوافق والتشغيل: إمكانية تشغيله محلياً عبر `npm run dev`، أو تحزيمه كملفات ثابتة (Production Build) تعمل بدون أي خادم خارجي.

5. مراحل التنفيذ التفصيلية (Step-by-Step Execution Plan)
--------------------------------------------------------------------------------
المرحلة 1: إعداد هيكل المشروع وحزم العمل (Project Scaffolding)
- إنشاء مشروع Vite + React وتجهيز Tailwind CSS مع دعم RTL والخطوط العربية.
- إعداد المتغيرات اللونية وثيم الـ Cybersecurity الاحترافي.

المرحلة 2: بناء محرك البيانات والمصطلحات (Data Layer & Glossary)
- ملف المصطلحات التفاعلي (Terminology Dictionary) مع الشرح الثلاثي (مصطلح، تبسيط، مثال).
- بيانات الحالات الثلاث الموثقة مع المصادر الرسمية والمراجع والسيناريوهات.

المرحلة 3: بناء المكونات العامة (Reusable UI Components)
- شريط التنقل العلوي (Navbar) مع زر تبديل "وضع العرض 🎤" وتنبيه الأمان.
- مكون المساعد التفاعلي للمصطلحات (Glossary Modal / Tooltip).
- بطاقات التدفق ومخططات الأسهم التفاعلية (Step-by-step Flow Diagrams).

المرحلة 4: بناء مختبرات المحاكاة التفاعلية (The 3 Interactive Labs)
- مختبر إنستغرام: واجهة استعادة كلمة المرور + محاكاة هجوم التخمين + وضع الأمان والمقارنة.
- مختبر سناب شات: واجهة جلب الروابط + محاكاة SSRF الداخلي + فلتر الحماية والشبكات الخاصة.
- مختبر شوبيفاي: لوحة الملفات + محاكاة طلب كائن IDOR + مصفوفة مقارنة (AuthN vs AuthZ).

المرحلة 5: صفحة المقارنة الشاملة ووضع العرض (Comparison & Presentation Mode)
- صفحة "ماذا تعلمنا من الحالات الثلاث؟" مع مخطط الدفاع متعدد الطبقات.
- ميزة "وضع العرض" (Fullscreen Presentation Stepper + نصوص "ماذا أقول؟").

المرحلة 6: الفحص والاختبار النهائي (Verification & Polish)
- اختبار كافة الأزرار، السيناريوهات (المصابة والآمنة)، والتوافق الكامل مع RTL.
- مراجعة دقة المصطلحات والمراجع الرسمية لتكون جاهزة 100% أمام لجان التحكيم والمهندسين.
